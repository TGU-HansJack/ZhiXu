# 编辑器详细方案（Zhixu Android）

目标：在 **v0.1 就把“写 Markdown + 写任务 + 可预览”做稳定**，并且从一开始就与 Zhixu 的语义核心保持一致（见 `docs/task-syntax.md`、`docs/vault-spec.md`、`docs/sync-protocol.md`）。

## 核心约束（不走弯路）

- 数据即文件：编辑器直接读写 `VaultRoot/docs/*.md`（见 `docs/vault-spec.md`）
- 任务身份稳定：任务唯一标识是 `@id(<ulid>)`，需要可写回 Markdown（见 `docs/task-syntax.md`）
- 索引是派生：SQLite/FTS 只服务检索与提醒，坏了可重建
- 同步是文件级：不做“聪明合并”，冲突通过冲突文件 + 冲突中心解决（见 `docs/sync-protocol.md`）

## 1) 编辑器模式设计（分阶段）

### v0.1（MVP）— 源码模式 + 简单预览

最低可交付（允许先简后全）：**纯文本编辑 + 手动保存 + 全屏预览**；语法高亮与自动保存可以作为 v0.1.1 增量迭代补齐（不改变数据与语义约束）。

**源码模式（默认）**

- 基础 Markdown 编辑：原生文本编辑体验优先（IME、选择、撤销、性能）
- 语法高亮（基础）：标题、列表、引用、代码块、粗体/斜体、链接（可先“够用”，不追求 100% 规范）
- 任务语法高亮：对 `- [ ]`、`- [x]`、`@due(...)`、`@done(...)`、`@tag(...)`、`@id(...)` 做特殊样式
- 基础编辑能力：
  - 撤销/重做（限长栈，避免内存膨胀）
  - 查找/替换（文档内）
  - 行号显示（可选：若实现成本高，可后置到 v0.2）
- 简单预览：按钮切到全屏预览（只读），用于验证排版与任务渲染

**MVP 任务交互（可选但高价值）**

- 光标在任务行时提供“切换完成/未完成”的快捷操作（更新 `- [ ]/- [x]`，必要时补 `@done(...)`）
- 通过快捷插入生成任务字段（`@due/@tag/@id`），减少用户手写成本

### v0.2 — 分屏预览模式（效率）

- 分屏：源码/预览左右布局（或上下，取决于屏幕与横竖屏）
- 实时预览：编辑时增量刷新预览（节流 + 增量渲染）
- 同步滚动：近似同步（按“可见行/段落锚点”映射，不追求像素级一致）
- 预览中任务交互：高亮任务并提供“勾选/取消”按钮（操作会写回源码）

### v0.3+ — 任务视图模式（管理）

- 任务提取：自动识别当前文档（或全库）任务并列表展示
- 任务管理：完成/未完成切换、编辑 due/tag/priority、设置提醒
- 任务过滤：按日期、标签、状态、优先级筛选
- 与索引联动：任务视图基于索引库查询（更快），但可回跳到源文档定位行

## 2) Android 端技术实现（建议实现路线）

### 源码编辑器（v0.1 优先稳定）

UI：Jetpack Compose 负责页面结构与工具栏，文本编辑用两种实现路线择一：

**路线 A（推荐 v0.1）：Compose + AndroidView 包装原生 EditText**

- 使用 `AndroidView` 承载 `AppCompatEditText`（获得成熟的选择/IME/长文本性能）
- 语法高亮：基于 `Spannable` 对可见范围增量着色
  - 以“行”为单位维护 token（减少全量重算）
  - 对代码块/多行结构使用轻量状态机（避免复杂正则灾难）
- 任务语法：对 `- [ ]/- [x]` 与 `@xxx(...)` 做分组着色；必要时在行首绘制 checkbox（或仅高亮 + 工具栏按钮）
- 撤销/重做：自维护 edit history（文本差异或快照），并在输入法组合文本时做保护

**路线 B（v0.2+）：纯 Compose 文本编辑组件**

- 可用于更深度的“结构化编辑”与分屏联动
- 风险更高：需要自行处理选择、IME、长文档性能；不建议 v0.1 作为主路线

### 预览渲染器

- Markdown 解析：引入 Markdown AST 解析库（例如 CommonMark 系列），生成结构化节点
- 渲染：将 AST 渲染到 Compose（Text/ClickableText/LazyColumn）
- 任务特殊渲染：
  - checkbox + 文本样式（完成态删除线/降强调）
  - 点击 checkbox 触发“写回源码并保存”
- 主题：统一走 Material 主题色，暗色/亮色下保持对比度

## 3) 编辑器与任务管理集成

### 任务语法支持（与 Shared Core 对齐）

Zhixu 的任务语义以 `docs/task-syntax.md` 为准：

- 识别 `- [ ]/- [x]` 与字段：`@id(...)`、`@due(...)`、`@done(...)`、`@tag(...)`
- 对未知字段 `@xxx(...)`：保持原文并可高亮为“扩展字段”（向前兼容）

### 快捷插入（减少输入摩擦）

- 工具栏提供：插入任务行、插入 `@due(...)`、插入 `@tag(...)`、插入 `@id(...)`
- 插入 `@id(...)`：
  - 当用户创建新任务（快捷插入）时立刻生成 ULID
  - 当用户勾选/编辑任务且缺 `@id(...)` 时补齐（写回文件）

### 任务状态切换（写回策略）

- 勾选完成：`- [ ]` → `- [x]`，并补/更新 `@done(YYYY-MM-DD HH:mm)`
- 取消完成：`- [x]` → `- [ ]`，`@done(...)` 可删除或保留（建议 v0.1 先保留原字段，仅更新 checkbox；v0.2 再提供策略开关）
- 不“就地智能合并”：任何写回都是对当前文件内容的确定性变换，交给同步层处理文件冲突

## 4) 编辑器状态管理

### 状态设计（建议）

- 编辑状态：文本内容（内存）、光标位置、选中范围、输入法 composing 区
- 视图状态：模式（源码/预览/分屏）、分屏比例、滚动位置
- 文档状态：SAF Uri/路径、最后修改时间、dirty 状态、同步状态（待同步/同步中/冲突）
- 任务状态：当前文档任务列表（解析结果）、任务完成/到期信息（派生）

### 状态持久化（v0.1）

- `DataStore`：保存用户偏好（主题、字体大小、是否行号、是否分屏等）与“最近打开文档”
- 编辑器会话恢复：
  - 保存光标位置/滚动位置（按文档 Uri key）
  - 自动保存：输入节流（例如 800–1500ms debounce）写回文件
  - 退出/切后台强制 flush（避免丢失）

注意：SAF 写文件成本高且可能失败，自动保存需“可恢复”：

- 写入采用临时文件/原子替换策略（如 SAF 支持）或“先写到 app private 缓存再提交”
- 写失败时提示并保留草稿（草稿存 app 私有目录，不写入 Vault）

## 5) 维护与扩展（架构建议）

- 模块化：`feature-editor`（UI/交互） + `core-parser`（Markdown/任务解析） + `core-tasks`（任务变换）分离
- 接口抽象：定义 `EditorEngine`（源码编辑/预览/分屏共享协议），便于未来新增模式
- 依赖注入：Hilt 管理 editor/renderer/parser/sync 状态协作
- 核心逻辑分离：任务解析、任务行变换（toggle/insert id）放 Shared Core，UI 只负责触发与展示
- AI 集成点：在“选中文本/当前段落/当前文档结构”上预留 action（补全/摘要/提取任务）

## 6) 性能优化策略（从 v0.1 预埋）

- 高亮增量：只处理可见行 + 邻近缓冲区；输入频繁时节流
- 大文档策略：
  - 高亮可按“段落块”异步计算并逐步应用
  - 预览渲染使用 `LazyColumn`，避免一次性渲染整篇
- 缓存：
  - Markdown AST/渲染结果按文档版本 hash 缓存（短期）
  - 图片附件缩略图缓存（v0.2+）

## 7) 与 Zhixu 架构集成点

- Shared Core：
  - 任务解析：与 `docs/task-syntax.md` 一致的解析器
  - 任务写回：对任务行做确定性变换（补 id、toggle、更新 due/done）
- SQLite 索引：
  - 编辑器保存成功后触发“增量索引”或标记待索引（WorkManager）
- 同步模块：
  - 文件修改后进入同步队列
  - 若检测到冲突文件（`conflict <timestamp> <name>.md`），编辑器提供入口跳转与对比（v0.3+）
- 平台能力：
  - SAF：Vault 目录与文档读写
  - 通知：任务提醒（由索引/任务模块产出 next_fire）
  - 附件：图片插入（写入 `attachments/` 并在 Markdown 中引用）

## 8) 用户体验设计（优先级）

v0.1 必须舒服：

- 工具栏：查找、撤销/重做、预览切换、任务插入
- 任务行操作：光标在任务行时一键切换完成状态

v0.2+ 增强：

- 外接键盘快捷键：Ctrl+B/I 等（实现方式取决于 EditText/Compose 路线）
- 拖拽/分享导入附件：自动写入 `attachments/` 并插入链接
- 横竖屏与大屏：分屏比例记忆、多窗口兼容

## 9) AI 功能预留点（不影响 MVP）

- UI：工具栏预留 “AI” 入口（先隐藏/灰置）
- 数据：解析阶段保留结构化上下文（段落边界、标题层级、任务列表）
- 接口：对外暴露 `complete(text, context)`、`summarize(doc, context)`、`extractTasks(doc, context)`（v0.2+）

## 10) 开发优先级（与路线图对齐）

- v0.1：稳定源码编辑器（纯文本编辑 + 手动保存起步）+ 全屏预览 + 任务语义写回
- v0.1.1：任务/Markdown 基础高亮 + 自动保存（输入节流 + 可恢复）
- v0.2：分屏预览 + 任务交互增强 + 搜索/替换体验完善
- v0.3：任务视图 + 同步增强（冲突中心/日志）
- v0.4+：AI 辅助与会议能力（OCR/录音/转写/行动项）
