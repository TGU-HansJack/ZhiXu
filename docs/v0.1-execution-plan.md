目标：把「本地 Vault + Markdown 编辑 + 任务语义写回」做稳，确保每一步都能独立交付可用价值。

相关规范：
- Vault：`docs/vault-spec.md`
- 任务语义：`docs/task-syntax.md`
- 编辑器：`docs/editor-spec.md`

## v0.1 范围（In / Out）

In（必须交付）
- Vault 选择：使用 SAF 选择 `VaultRoot/`，并持久化权限。
- Vault 结构：首次进入自动确保 `docs/`、`attachments/`、`.zhixu/` 存在；创建示例 `docs/Inbox.md`（或等价入口文档）。
- 文档管理：列出 / 新建 / 删除 `docs/*.md`；点击进入编辑。
- 编辑器：纯文本编辑体验优先；支持手动保存；提供一键 Preview（Markdown 渲染）。
- Tasks（最小闭环）：保存时为缺失 `@id(<ulid>)` 的任务行补全并写回文件（见 `docs/task-syntax.md`）。

Out（v0.1 不做 / 仅预留）
- WebDAV / Git 同步实际传输逻辑（仅保留入口与协议对齐）。
- SQLite 索引 / 全局搜索 / Today & Upcoming 视图。
- 编辑器增强（v0.1.1）：Markdown/任务语法高亮、自动保存、撤销/重做等。
- 复杂 Markdown 能力（所见即所得、100% 规范渲染、分屏实时预览）。

## 交付物与验收（Definition of Done）

### 1) Vault 与权限
- 首次启动能引导选择目录；已选目录重启后仍可用。
- 若权限失效/目录不可访问，UI 给出明确提示，并能重新选择。

### 2) 文档列表（docs/）
- 空库有明确空态（含“新建文档”入口）。
- 列表点击进入编辑；删除需要二次确认。
- 新建文档名冲突有处理策略（例如自动追加序号或提示用户修改）。

### 3) 编辑器（源码模式 + Preview）
- 能加载/编辑/保存 Markdown；保存失败有可理解的错误提示。
- Preview 与源码切换不丢内容；大文档滚动与输入基本可用（不卡死）。

### 4) Tasks：写回稳定 ID
- 支持最小任务语法 `- [ ]` / `- [x]`。
- 保存时：仅在缺失 `@id(...)` 时插入；已存在的 `@id(...)` 不改变。
- 插入后显示“已保存（补全 N 个 id）”或等价提示。

## 建议里程碑（可按 PR/提交分段）

- M1：Vault 选择 + 结构确保 + 示例文档
- M2：文档列表 + 新建 + 删除（全部基于 `docs/*.md`）
- M3：编辑器加载/保存 + Preview（先可用后优化）
- M4：Task 语义：保存时 normalize + `@id(...)` 写回
