# Zhixu（知序）· 原生优先方案 A（聚焦核心问题版）

## 1) 先解决最重要的事：核心问题

用户的核心痛点是：**信息管理混乱**与**多端同步困难**。因此前期收敛到三件事：

- 文档管理：以 Markdown 为主的笔记系统（文件即数据）
- 任务管理：待办 + 提醒（从 Markdown 或独立任务列表出发）
- 多端同步：优先 WebDAV（MVP），Git 作为可选同步方式/后置能力

## 2) 产品定位与差异化

定位：**AI 原生的个人知识与任务管理系统**，并为会议场景做优化。

- AI 原生设计：从数据结构与接口层预留 AI 能力（摘要/补全/提取任务/RAG），而不是后贴插件
- 会议场景专注：录音、转写、OCR、行动项一体化（阶段性落地）
- 原生性能与体验：Android 原生优先，保证稳定与响应
- 隐私优先：数据本地化；同步可加密；可离线使用
- 开源策略：用开源客户端建立社区与贡献入口

## 3) 实现策略：小步快跑（MVP 分阶段）

原则：

- 现在：Android 原生 UI，稳定第一
- 统一：数据格式、协议、语义（跨端一致）
- 未来：Web / Desktop 复用“核心”，而非复用 UI

### v0.1（MVP：验证核心需求）

- 基础文档管理：创建/编辑/删除（Markdown），文件直读写
- 简单任务管理：待办列表（最小语法支持）+ 基础提醒
- 同步：v0.1 先预留入口并对齐协议；WebDAV 落地到后续迭代（见 `docs/sync-protocol.md`）
- 基础 Android UI：文档列表 + 编辑器 + 任务入口

### v0.2–v0.3（迭代：建立独特优势）

- 任务系统：提醒完善、优先级/分类/筛选
- AI 基础能力：摘要/补全/提取行动项（先本地接口，后接服务）
- OCR：把图片/附件中的文字变成可搜索的文本
- WebDAV 同步：全量同步 → 增量同步；冲突中心与同步日志
- 同步增强：冲突中心、同步日志、更稳健的增量策略；可选 Git 同步方案

### v0.4+（扩展：完善会议场景与知识库）

- 录音：会议记录进入附件体系
- 转写：对接云端转写（可收费能力）
- RAG 知识库：基于个人库的问答与检索增强
- 跨平台：从 Android 走向 Windows（复用核心）

## 4) 架构约束（保证后续可扩展）

结论：**不做「Web 内核作为当前 UI」**，采用 **原生 UI + 共享核心**。

- UI / Presentation：Android 原生（Kotlin + Jetpack Compose）
- Shared Core：纯 Kotlin（可迁移 KMP），负责解析/索引/同步/任务/AI 接口
- Data & Platform：SAF/SQLite/通知/录音/OCR 等平台能力
