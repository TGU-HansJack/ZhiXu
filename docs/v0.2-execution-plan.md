# v0.2 执行计划（效率：索引 + 搜索 + 任务闭环 + WebDAV MVP）

目标：在 v0.1「文件即数据」的前提下，把“找得到、管得住、能同步”做成可日用版本。

相关规范：
- Vault：`docs/vault-spec.md`
- 任务语义：`docs/task-syntax.md`
- 同步协议：`docs/sync-protocol.md`
- WebDAV MVP 落地：`docs/webdav-mvp-plan.md`

## v0.2 范围（In / Out）

In（必须交付）
- 索引库：在 `.zhixu/index.sqlite` 建立可重建索引（docs / tasks / attachments 元数据 + FTS）。
- 搜索：标题/正文全文检索 + 任务聚合检索（快速定位到文档）。
- 任务闭环：
  - Today / Upcoming 列表（基于 `@due(...)`）
  - 勾选完成/取消完成（写回 Markdown，不做聪明合并）
  - 基础筛选：状态（done/undone）、tag
- 提醒：从索引产出最近触发时间，WorkManager/AlarmManager 实现最小提醒。
- WebDAV MVP：全量同步整个 Vault + 最小日志 + 失败可恢复（见 `docs/webdav-mvp-plan.md`）。

Out（v0.2 不做 / 可后置）
- WebDAV 增量同步与冲突中心 UI（v0.3）。
- 重复任务（`@rrule`）与复杂优先级体系（可部分预留）。
- 预览分屏与复杂编辑器交互（可并行推进，但不作为 v0.2 阻塞项）。

## 数据与边界（必须遵守）

- 真数据：`docs/*.md`、`attachments/*`、`.zhixu/settings.json`
- 派生数据：`.zhixu/index.sqlite`（可删除重建）
- 写回原则：任何任务状态变化都必须写回对应 Markdown 文档，索引仅做加速。

## 交付物与验收（Definition of Done）

### 1) Index（可重建）
- 首次索引：扫描 `docs/`、解析任务行，构建 FTS。
- 增量索引：文档保存/同步完成后可触发“增量更新”或标记待更新（WorkManager）。
- 索引损坏可恢复：删除 `.zhixu/index.sqlite` 后可重新完整构建且不丢数据。

### 2) Search（可用）
- 搜索支持：标题/正文关键字；返回结果能打开文档并定位（定位可先粗略：打开文档并高亮首个命中）。
- 性能底线：1k 文档/10MB 文本量级下搜索能在可接受时间内返回（可先定目标为 < 1s 冷缓存、< 300ms 热缓存，按设备调整）。

### 3) Tasks（闭环）
- Today / Upcoming：按 due 时间排序；展示来源文档与标题。
- Toggle 完成：从任务列表点击能写回 Markdown 并刷新列表；`@id(...)` 必须保持不变。
- 容错：解析失败不阻塞 UI，失败的任务行可在任务详情中提示“原文”。

### 4) Reminders（最小可用）
- 对 due 任务产出提醒：到点通知 + 点击跳转到任务来源文档。
- 取消/更新：任务完成或 due 变更后，提醒能正确取消/重排。

### 5) WebDAV MVP（全量同步）
- 首次同步：能把一个 Vault 从设备 A 迁移到设备 B（含 attachments）。
- 失败可恢复：中断/网络错误后可重试继续；不导致本地数据丢失。
- 最小日志：至少记录同步开始/结束、上传/下载数量、失败原因（可写 `.zhixu/sync/log.jsonl`）。

## 建议里程碑（按 PR/提交分段）

- M1：SQLite schema + Index 重建（docs 元数据 + FTS）
- M2：任务解析入库 + Today/Upcoming（只读）
- M3：任务 toggle 写回 + 列表刷新（闭环）
- M4：提醒调度（最小通知）
- M5：WebDAV MVP（全量同步 + 日志 + 失败可恢复）
