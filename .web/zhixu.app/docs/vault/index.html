Vault 规范

目标：可迁移、可导出、索引可重建。

目标

  • 数据不被应用锁死：任何时候都能把 Vault 复制到别处继续使用。
  • 索引可重建：删除索引库不等于丢数据。
  • 同步以文件为单位：协议更简单、冲突更可追溯。

目录结构

VaultRoot/
├─ docs/                 # 全部 Markdown 文档
├─ attachments/          # 图片 / 音频 / 文件
└─ .zhixu/
   ├─ index.sqlite       # 索引库（可删除重建）
   ├─ settings.json      # Vault 设置
   ├─ sync/              # 同步元数据/冲突日志
   └─ exports/           # 导出产物（可选）

导出规则

  • 最小导出：docs/ 与 attachments/
  • 完整导出：整个 VaultRoot/（可选加密压缩）

“真数据”与派生数据

  • 真数据：docs/*.md 与 attachments/*
  • 派生数据（可重建）：.zhixu/index.sqlite、.zhixu/sync/*

命名建议

  • 文档文件名由用户自由命名，不强制 UUID 文件名。
  • 任务身份通过行内 @id(...) 保持跨端稳定，见 任务语法。
